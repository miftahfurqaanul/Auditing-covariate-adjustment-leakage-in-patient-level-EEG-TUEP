# ADDENDUM 1 to PRAREGISTRASI_putaran42.md (2026-10-23, written after the LR and XGB families finished but BEFORE the XGB, RF, Tang, or NM results were seen; the LR results had been seen: all R1 "tidak ada bukti" (no evidence), K1 6/6, see the report)

1. **Device deviation for XGB-Rohira.** The empty environment variable `CUDA_VISIBLE_DEVICES` was inherited from the launching shell, so XGBoost (`device="cuda"`) automatically switched to CPU ("No visible GPU is found, setting device to CPU"; confirmed with a small test). All 120 XGB units (120 = 20 replicates x 2 conditions x 3 gamma) were run on CPU with `tree_method="hist"` and the same hyperparameters (100 trees, depth 6, rate 0.1). The algorithm is the same; the only difference is the device (float32 histogram precision on the GPU may give slightly different trees). The XGB results were not rerun on the GPU; the deviation is reported.
2. **Tang and NM** were run on the GPU with `CUDA_VISIBLE_DEVICES` unset (fixed in `run_chain_42_gpu2.sh` and `round42_gpu_nn.py`).
3. **Implementation details not covered by the parent:** (a) covariate caliper: the 199 Tang patients (one patient without per-second data) use y_sim from the 200 patients restricted to 199; the 5 folds are stratified by y_sim; the 20% validation is stratified by y_sim (`tang_fixed.split_val`); (b) the rank transform for Tang is fitted on a subsample of 100,000 seconds of training+validation patients (fixed seed), 1,001 quantiles, interpolation, u clipped to [0.001, 0.999]; (c) NM: maximum 20 epochs, d = L = 32 fixed (as in `round38_nm_paired.null_fold`; no configuration selection), one seed per fold; the NM label `normmamba.Y` is replaced by y_sim during the replicates; (d) the rank transform for NM is fitted on the training-patient segments; (e) Tang uses 'pat' = OLS on the per-patient mean (Lp, unweighted), pool = training + validation.
4. GPU order: Tang then NM. Replicates: Tang 20 and NM 20 (gamma 0 and 1; H1). No scope adjustment.

5. (Note on the cause, added before the XGB/RF/Tang/NM results were seen; this file is hashed again below.) Cause of the hidden GPU: `round28_analisis` (imported through `round42_common`) sets `CUDA_VISIBLE_DEVICES=""` at import. The GPU scripts now delete that variable after all imports and before CUDA is initialized. The same explains XGB on CPU (item 1).
